## Acceptance

List observable outcomes. Give each an ID and required verifier IDs. For example: A1 — retrying an export produces exactly one row per record; required verifier: export-retry.

## Evidence

For each acceptance ID, record verifier ID, status, tested revision/snapshot, command or procedure, expected and observed result, and artifact path. Keep unavailable proof explicitly blocked.

## Handoff

Record changes, outstanding checks, process/run IDs, next action, and any required review decision. Use states draft → ready → in_progress → review → done, with blocked available from active work. Resolve blockers before returning to ready; a failed review returns to in_progress.

This template is for a single-worker pilot. When adopting an issue tracker, move these fields into its task record and use its native status and ownership model.
